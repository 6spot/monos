## Write ownership and dependency order

Workers preserve other changes; they do not commit, push or alter task lifecycle.
All assignments carry this task identity and scoped specs; no child dispatch loops.

1. **Sole protocol writer**: schema, fixtures, validation, generated TS/Go/OpenAPI;
   freeze exact Owner command/read and TaskReviewSource/Agent shapes with backend.
   No dependent source/Web edits before concrete type handoff.
2. **Backend authority/source owner**: migration25/registry, new review modules,
   canonical review result helper, actual Owner receipts/SQL revocation, feedback
   routing/source scheduler/reads, Conversation reconsideration, Requirement and
   Replan origin/successor, common input guards/Node invalidation integration, and
   real PG fixtures/tests. Coordinate shared service/scheduling/source files first.
3. **Main delivery/Runner integration after handoff**: app/main routes/pumps,
   owner-delivery/remote-preparation stale authority, original effect settlement,
   revoked status and Cancel reconciliation projection; canonical output helper
   consumption. Go daemon/local/wire/Host/CLI accepts exactly the new Planner phase,
   preserves peer/Stop/journal attribution and exclusive sources.
4. **Web owner after shared type freeze**: exact review API/journal UI, Request
   Changes, feedback/source/settlement and explicit exits; Replan source/successor
   display/session fences and cancelled effect truth. Genuine protected-route/PG
   browser fixture; existing Base UI/layout reused.
5. **Main integration**: independent review/fixes, current input reconciliation,
   smallest missing checks, owning spec updates, AC evidence, scoped work commit,
   archive/journal and next combined installed acceptance leaf.
