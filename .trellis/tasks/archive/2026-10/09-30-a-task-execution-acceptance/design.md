## Boundaries and ownership

Root owns acceptance artifacts, installation/preflight/rollback decisions, browser
Owner actions and exact native/evidence audits. Existing implement-role worker owns
task-specific staging/package/build utilities and Linux build results; it may read
host and run temporary build/test containers, but cannot replace/restart services,
change Owner configuration or start model work. The reviewer owns independent
script/provenance/quality review, with no duplicate native trial. The original
workers are unavailable in the resumed session; replacement implement/check
workers continue the same ownership and preserve their predecessors' evidence.
No product file changes are expected. One-time private helpers remain hash-addressed
acceptance evidence; durable reproduction/decisions are recorded under this task.

## Native path

Use a fresh Project/resource/Role and one assigned Todo; repository is the authorized
`6spot/monolab-feasibility-20260928-160020-public`. Remote preparation is after
acceptance. Recheck actual remote HEAD/default branch and model catalog before
admission. Prefer a small new dependency-free function plus meaningful tests based
on the repository's actual contents. The Owner supplies desired behavior, never a
prewritten implementation or a native driver command. Ordinary installed Planner
prompts/monos tools must produce preview and Plan and complete the Node.

Browser uses a temporary SSH TLS forward to existing monos, actual built SPA and
same-origin session. Retain command JSON before send and response metadata after;
never retain Cookie/Authorization/password/private keys in public artifacts.
X-Monos-Session must bind actual Task actions. Unknown outcomes use the same receipt
identity and normal UI recovery. No __test__ route is available or permitted.

Capture passive/pre-Start checkpoints, then native source/dispatch/physical identity
while active where feasible. Root SQL/SQLite/Git reads establish canonical lineage
and exact workspace/completion facts, not mutate lifecycle. Completion must release
physical work and all leases/effects before final REVIEW acceptance. Independently
check tree/file bytes and requested behavior from the finalized result.

## Continuity and visual evidence

One actual chain supplies Todo/preview/Task/local REVIEW images at both required
viewports. Inspect long content/actions/focus and exact identifiers; record source/
asset/image hashes. Browser reload must reconstruct current result and drafts without
new execution. Existing recovery matrix covers live holds, native Stop/revision/
Replan, idle restarts and historical reboot with its manual-start limitation.
Do not force a Stop race or repeat service restarts unless candidate evidence exposes
a missing invariant. Installing changed components provides new reconnect evidence
for preserved historical data; distinguish it from a post-new-Task restart.

## Failure handling

A timeout is an observation failure, not a Runtime outcome. Retain exact failed
stage and inspect current IDs; use supported exact Owner Retry/Withdraw/Stop/Cancel.
A model issue may receive concise Owner clarification, recorded as intervention.
No silent fixture fallback. Final ledger owns every created record/helper/transport;
retain immutable results while removing only task-owned temporary transports/processes.
