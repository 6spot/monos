## Verified provider baseline (2026-10-03)

GitHub documents a warning above 50 MiB and a block above 100 MiB for ordinary
Git files. The latter is a provider hard limit, separate from local capture and
Owner policy; adding LFS handling is outside this leaf.
[GitHub large-file rules](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

Git access with an App requires Contents permission; editing Actions files
under `.github/workflows` additionally needs Workflows permission.
[GitHub App permission guidance](https://docs.github.com/en/enterprise-cloud%40latest/apps/creating-github-apps/registering-a-github-app/choosing-permissions-for-a-github-app).
Reference updates expose a force flag; false/default enforces fast-forward.
[GitHub reference API](https://docs.github.com/en/rest/git/refs).

These primary documentation checks establish adapter policy inputs, not a live
permission observation or a successful publication. Unknown/unavailable current
provider authorization cannot be relabelled granted. No provider mutation was run.

## Decisions converged into design

The reviewed [design](../design.md) selects 50 MiB local policy, separate >100 MiB provider file bound, explicit finite streamed credential rules and complete bounded page evidence. Local retry/eligible override issuance is included; actual provider permission observation remains the next leaf and unknown stays blocking. No-change requires Runner base/result tree comparison before creating a Delivery item. A terminal incomplete scan is immutable; explicit Retry makes a new run over the same frozen candidate, while interrupted processing resumes the same operation. Exact verified-baseline inherited credential exposure has a noneligible remediation finding. Task activated under standing authorization on branch `feat/stage-a-boundary-probe`; current contexts validate (23 implementation, 26 check entries), with explicit truncated-source fallback required.

The source research questions addressed were:

- Exact source identity, verified parent evidence and durable operation/result
  signatures; current versus retained historical candidate projection.
- Rule/config/provider-permission snapshot digest and concrete complete-scan
  bounds. Exceeded processing bounds must block explicitly, never pass a partial
  scan. Inspection, capture, publication and scan budgets are separate.
- Minimum explicit credential-pattern rules and safe redacted finding facts;
  scan introduced versions and final tree without returning matching values.
- Eligible override receipt binding (Task/effective basis/source tree/candidate
  parents/scan/rules/config/findings). Hard limits and missing permission are
  never eligible. Product Owner remains the only receipt authority.
- Automatic local prep and retry/recovery, with no remote write in this leaf;
  deferred remote preparation still retains local candidate/findings.
- Existing Task Overview Review surface, bounded complete finding pagination,
  original source-to-public-head mapping, desktop/mobile failure/history states.

Remote branch/PR/check/merge operations, acceptance/frozen delivery finalization,
Request Changes delivery recovery and installed integration remain later leaves
in the already recorded order. Multi-repository partial delivery and plain-Git
finalization remain later V1 slices; retain provider-neutral collection seams.
