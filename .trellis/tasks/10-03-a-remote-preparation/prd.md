# Automatic review preparation

## Goal and value

Prepare and reconcile one stable GitHub delivery branch/PR from the exact current
local result, while Owner Review and local inspection remain usable through
provider failures, pending input, cancellation and restart.

## Planning status and authorization

Converged source-backed scope after upstream local candidate acceptance1ad5735.
User delegates successive planning, implementation, routine decisions, scoped
commits and already authorized synthetic effects without further permission asks.
Development authority does not create product Owner override or Accept receipts.

## Dependency

[Controlled local candidate](../archive/2026-10/10-03-a-publication-candidate/prd.md),
accepted2026-10-04. Parent order remains publication candidate→remote preparation→
Owner delivery→correction/recovery→combined delivery acceptance.

## Confirmed facts

Current source supplies exact local candidates/scans/pages/Owner receipts but no
remote push lane, PR coordinator or Cancel closure. New remote admission needs
canonical taskInputGuards in addition to localAdmissionAllowed. Existing App
access is read-only; production workflow permission is unknown. Source result,
effective basis and published ancestry are distinct. Prior provider experiments
prove bounded GitHub behavior, not the new coordinator.

Live read-only inventory found zero GitHubApp configuration rows in the existing
monos installation. Active ghOAuth6spot is an authorized synthetic account, not an
App installation grant. Keep production App issuer tests separate from real
synthetic lower-level effect trials; fully installed liveApp issuance remains an
external configuration gate for later combined delivery acceptance. No key or
installation identity is fabricated.

## In scope

- StageA automaticGitHub preparation only, with durable Delivery-owned operations,
  one stable itembranch/PRmarker, complete current exact scans/overrides and fresh
  source/effective/config/permission/input/physical guards at each new mutation.
- Service-only exact-ref nonforce fast-forward push, advertised-head guard,
  immutable private intent/results and observe-before-retry after uncertainty.
- Actual reconciled published-head proof for later source corrections, preserving
  private history and original source attribution. No-change compares the verified
  delivery parent; reversion to original base is a real FF correction.
- Explicit same-tree new-source→existing published-result mapping preserves the
  old manifest and item/head without pretending a new construction was pushed.
- Backend PR create/update/lookup and exact-head statuses/checks/mergeability
  polling, deterministic safe Task title/completion/reference content, bounded
  schedules/cooldown, truthful incomplete/stale/unknown observations.
- Exact authenticated Retry and receipt recovery, local-readable remote progress
  and failure UI. No Owner PreparePR button.
- Minimal Cancel cleanup: terminal cancellation revokes new preparation, reconciles
  admitted effects, closes the exact undeliveredPR and keeps its branch. Missing
  access retains cleanup attention. Revision/Replan/guidance publication waits
  for admitted remote effect quiescence without borrowing their owning slots.

## Out of scope

No Accept/merge/RequestChanges or accepted-batch setter; no new Task states,
generic workflow engine, teams, webhook requirement, multi-repository partial
finalization, plain-Git delivery, full after_acceptance remote preparation,
cross-Runner transfer, permanent disk-loss recovery, arbitrary executable/URL/ref
or provider history rewrite. Existing after_acceptance stays local-only with zero
remote mutation/write-token requests. Never push monos product source.

## Acceptance criteria

- [x] Exact candidate/native synthetic Git push plus real authorized GitHub branch/PR trial retains one stable identity, no private ancestry or force push; evidence separates injected synthetic token from production App issuance.
- [x] Actual PG worker/restart/message/revision/Cancel races and physical Git crash/ack tests reconcile original effects before successors, with no duplicate PR create after lost response.
- [x] Changed source/basis/config/mode or unresolved input blocks new writes; late historical success cannot restore authority; deferred mode creates no remote writes.
- [x] Current-head check/status/mergeability and deterministic PR content survive bounded poll/rate-limit/unknown outcomes; stale heads never appear current successful.
- [x] Actual Cancel before/during/after remote preparation reconciles and closes only the exact ownedPR, retains branch and terminal Task; uncertain/access-denied cleanup remains visible.
- [x] Protected builtSPA scoped Retry/receipt/session fences and inspected desktop/mobile preparing/failure/check/history/cleanup states preserve exact local inspection.
- [x] Generated protocol, migration22→23, affected quality gates and independent combined review bind final source/evidence; executable spec captures all introduced cross-layer contracts.

## Key decisions

See design.md and research/. Unknown started push observing expected/absent ref is
conservative possible-publication attention, not proof of nonexecution. Unknown
PR create with zero visible matches never repeats POST. Foreign/manually closed
PR never creates replacement identity. Checks are exact-head information; required
check authorization/protection readiness is owned by the next delivery leaf.
