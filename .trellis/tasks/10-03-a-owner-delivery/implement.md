## Ownership and dependency order

Workers do not commit/push/lifecycle/revert. Native context injection with explicit
assigned task and child fallback. Main owns integration/specs/evidence/commits/archive.

1. **Contract/persistence:** single owner of schema/fixtures/generated outputs,
   migration24/registry and acceptance commands/state/reads. Freeze actual bounds,
   variants/manifest/receipt/read shapes and hand off concrete types before dependent
   UI/coordinator code. Implement canonical enumeration, SQL receipt authority,
   atomic cutoff/local-only completion and focused real PG tests.
2. **Provider:** independent new github-finalization module/tests; coordinate any
   github-remote/github edits. Exact readiness/method/response classifiers and bounded
   adapter; then integrate accepted worker profiles/checkpoints under frozen contract.
   No DB acceptance or prep/Cancel ownership.
3. **Accepted coordinator after schema handoff:** own accepted worker, preparation
   operation links/access before/after token, shared item owner, ordinary freeze,
   scheduler/reactivation and Cancel. Serialize shared edits with contract owner.
   Real PG before-first-PR/later conversation/restart/Retry/unknown merge/Cancel.
4. **Web after wire handoff:** owner-delivery feature/API, TaskIntent/receipt routes,
   Overview/conversation/Cancel and focused tests. Coordinate all generated/shared files.
5. **Main:** app/main wiring, cross-layer/SQL/provider review, fixes and honest evidence,
   owning specs/criteria, scoped commit/archive, then next correction leaf.
